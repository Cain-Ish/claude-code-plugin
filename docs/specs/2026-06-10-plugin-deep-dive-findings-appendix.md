# STRATEGIES (full)

## reliability & autonomy — The loop's bones are genuinely good: fail-soft exit-0 hooks, single-flight locking with stale-steal, drainer quarantine-after-3-failures, near-universal tmp+mv atomicity, and a strong meta-test culture, with healthy hot-path latency on the Pi. But every leg of capture→extract→consolidate→serve currently carries one structural defect that converts the unattended promise into manual rescues: recursive self-spawns burn every drainer slot (169 ec=124 kills), stop-extract re-archives its own output 18x over, the consolidation sandbox is physically impossible under the shipped systemd unit (100% auto_maintain failure, stuck pending dreams), embeddings silently break on every version bump, and search ranking is corrupted by an unbounded graph boost the eval gate cannot see. The shared meta-failure is that degradation is either silent or expressed as a SessionStart banner asking the human to run a command — nothing closes the loop, which is why cost-router sat inert and auto_maintain failed for weeks unnoticed. The seven proposals fix the five structural breaks and add the two missing layers (a self-healing `sb doctor` surface and deployment/latency observability) so the next failure class gets auto-fixed or loudly quarantined once, not nagged about.

WHY: HOOK-3: drainer's `claude -p` spawns re-enter the full plugin stack (247 nested session-load lines, 133 nested stop-extract gates, 60%+ of error-log volume).
