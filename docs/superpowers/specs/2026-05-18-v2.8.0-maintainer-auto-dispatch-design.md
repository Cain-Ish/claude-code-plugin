# v2.8.0 — knowledge-maintainer auto-dispatch on wiki-write threshold

**Status:** design approved 2026-05-18; ready for `writing-plans`.
**Author:** operator + Claude session 2026-05-18.
**Scope:** plugin-internal change. No data migration beyond a binary-flag → integer-counter swap.
**Target version:** 2.8.0.

## Problem

The `second-brain:knowledge-maintainer` subagent runs a 6-phase consolidation cycle (Hot-Tier Hygiene → Audit → Deduplicate → Relate → Enrich → Reindex) that materially improves wiki health: it fills empty descriptions/tags, builds bidirectional `related:` edges, rebuilds `wiki/index.md`, normalizes PROJECT.md files, and removes stale degraded breadcrumbs. The first four phases require an LLM in the loop and are only reachable via the subagent.

In v2.7.x the maintainer is **opt-in only**. After wiki writes, `merge-project-update.sh` calls `sb_set_maintainer_needed`, which sets a binary flag that `session-load.sh` surfaces as a SessionStart banner suggesting the user run the agent manually. In practice — observed in this session and confirmed by the user — the banner gets ignored, the relate/enrich phases never run, and BM25 search quality silently degrades while orphan/dead-link/empty-frontmatter counts grow.

This release closes the loop: once wiki writes accumulate past a threshold, the next SessionStart **auto-dispatches** the maintainer before the user's first response.

## Goals

1. The maintainer runs on a predictable cadence tied to actual wiki activity, not user memory.
2. Failures (auth broken, agent crash, parent-Claude ignores instruction) degrade gracefully: at most one stuck dispatch, never a wedged SessionStart, never an infinite retry loop.
3. The user retains full control via env-var kill switch and per-project disable marker.
4. The added complexity stays in three files (`lib.sh`, `merge-project-update.sh`, `session-load.sh`) plus tests; no new MCP tools, no CLI flag changes.

## Non-goals

- Expanding `knowledge_validate` autofix scope (separate v2.8.x candidate, not in this release).
- Lint orphan-exempt frontmatter mechanism for changelog pages (separate v2.7.3 candidate).
- Replacing the maintainer agent's internals — the subagent is unchanged.
- A general scheduler/cron framework — this is single-purpose.

## Architecture

```
┌────────────────────────────────────────────────────────────┐
│ STOP / PRECOMPACT HOOK                                      │
│   stop-extract.sh + pre-compact.sh                          │
│     → merge-project-update.sh                               │
│         → on wiki page write: sb_inc_wiki_writes(slug)      │
│             ↓                                               │
│     ~/.second-brain/projects/<slug>/.wiki-writes            │
│     (single ASCII integer, atomic write)                    │
└────────────────────────────────────────────────────────────┘
                       │
                       ▼ (next SessionStart)
┌────────────────────────────────────────────────────────────┐
│ SESSIONSTART HOOK                                           │
│   session-load.sh                                           │
│     reconcile previous dispatch (markers)                   │
│     if SB_MAINTAINER_AUTO != off                            │
│     and !auto-disabled                                      │
│     and .wiki-writes ≥ SB_MAINTAINER_THRESHOLD              │
│     then emit BLOCKING REQUIREMENT additionalContext        │
│       and touch .maintainer-dispatched                      │
└────────────────────────────────────────────────────────────┘
                       │
                       ▼
┌────────────────────────────────────────────────────────────┐
│ PARENT CLAUDE                                               │
│   Reads additionalContext                                   │
│   Invokes Agent tool: subagent_type =                       │
│     second-brain:knowledge-maintainer                       │
│   On return: write .maintainer-needed-last                  │
│   Print one-line banner; respond to user's prompt           │
└────────────────────────────────────────────────────────────┘
```

The maintainer subagent is unchanged. The only new wiring is the counter, the state machine, and the additionalContext template.

## State files

All under `~/.second-brain/projects/<slug>/`:

| File | Type | Lifecycle |
|---|---|---|
| `.wiki-writes` | ASCII integer | Created by `sb_inc_wiki_writes`; incremented per wiki page write; reset to 0 on success, N-1 on failure |
| `.maintainer-dispatched` | empty marker | Created by `session-load.sh` when banner emitted; consumed at next SessionStart |
| `.maintainer-needed-last` | empty marker (content "ok") | Created by parent Claude per the contract on successful subagent return |
| `.maintainer-fail-count` | ASCII integer | Increments on failure-detection; resets on success; at ≥ `SB_MAINTAINER_MAX_FAILS` triggers auto-disable |
| `.maintainer-auto-disabled` | empty marker | Hard-disables auto-dispatch for this project until user manually deletes |

The pre-existing `.maintainer-needed` binary flag is removed by the 2.8.0 migration step (see below).

## Helpers added to `scripts/lib.sh`

```bash
sb_inc_wiki_writes() {  # $1 = project slug
  local f="$BRAIN_DIR/projects/$1/.wiki-writes"
  mkdir -p "$(dirname "$f")" 2>/dev/null
  local n=0
  [ -f "$f" ] && n=$(cat "$f" 2>/dev/null || echo 0)
  case "$n" in ''|*[!0-9]*) n=0 ;; esac    # defensive: corrupt → 0
  printf '%d' "$((n+1))" > "$f.tmp" && mv "$f.tmp" "$f"
}

sb_get_wiki_writes() {  # $1 = slug → integer (default 0)
  local v
  v=$(cat "$BRAIN_DIR/projects/$1/.wiki-writes" 2>/dev/null || echo 0)
  case "$v" in ''|*[!0-9]*) echo 0 ;; *) echo "$v" ;; esac
}

sb_set_wiki_writes() {  # $1 = slug, $2 = int
  local f="$BRAIN_DIR/projects/$1/.wiki-writes"
  mkdir -p "$(dirname "$f")" 2>/dev/null
  printf '%d' "$2" > "$f.tmp" && mv "$f.tmp" "$f"
}

sb_reset_wiki_writes() { sb_set_wiki_writes "$1" 0; }

sb_inc_maintainer_fails() {  # $1 = slug
  local f="$BRAIN_DIR/projects/$1/.maintainer-fail-count"
  local n; n=$(cat "$f" 2>/dev/null || echo 0)
  case "$n" in ''|*[!0-9]*) n=0 ;; esac
  printf '%d' "$((n+1))" > "$f.tmp" && mv "$f.tmp" "$f"
}

sb_reset_maintainer_fails() { rm -f "$BRAIN_DIR/projects/$1/.maintainer-fail-count"; }

sb_get_maintainer_fails() {
  local v; v=$(cat "$BRAIN_DIR/projects/$1/.maintainer-fail-count" 2>/dev/null || echo 0)
  case "$v" in ''|*[!0-9]*) echo 0 ;; *) echo "$v" ;; esac
}
```

The existing `sb_set_maintainer_needed`/`sb_get_maintainer_needed`/`sb_clear_maintainer_needed` helpers are removed (replaced by the counter).

## Change in `scripts/merge-project-update.sh`

At the point where the merge writes or updates a page under `$KNOWLEDGE_DIR/wiki/`, increment the counter exactly once per merge invocation that touched at least one wiki page. (The call site is a single conditional branch after the wiki-write loop, so "at most once per merge run" is structural rather than an explicit cap.)

```bash
# Existing wiki-write branch (simplified):
if wrote_wiki_page; then
  [ -n "$PROJECT_SLUG" ] && sb_inc_wiki_writes "$PROJECT_SLUG"
fi
```

The previous call to `sb_set_maintainer_needed "$PROJECT_SLUG"` is removed.

## State machine in `scripts/session-load.sh`

Inserted after the existing project-slug resolution, before the existing dream/extractor-health banner emissions.

```bash
N=${SB_MAINTAINER_THRESHOLD:-3}
N_MAX_FAILS=${SB_MAINTAINER_MAX_FAILS:-3}
AUTO=${SB_MAINTAINER_AUTO:-on}
PROJ_DIR="$BRAIN_DIR/projects/$slug"
DISP="$PROJ_DIR/.maintainer-dispatched"
ACK="$PROJ_DIR/.maintainer-needed-last"
DISABLED="$PROJ_DIR/.maintainer-auto-disabled"

# 1. Reconcile previous dispatch.
if [ -f "$DISP" ] && [ -f "$ACK" ]; then
  # Success.
  sb_reset_wiki_writes "$slug"
  sb_reset_maintainer_fails "$slug"
  rm -f "$DISP" "$ACK"
elif [ -f "$DISP" ] && [ ! -f "$ACK" ]; then
  # Failure (timeout, agent error, parent ignored instruction).
  COUNT_AFTER=$(( N - 1 < 0 ? 0 : N - 1 ))
  sb_set_wiki_writes "$slug" "$COUNT_AFTER"
  sb_inc_maintainer_fails "$slug"
  rm -f "$DISP"
  sb_log_error "session-load.sh" "maintainer-auto-dispatch-failed slug=$slug" 0
  sb_append "$(printf '## ⚠ maintainer auto-dispatch failed last session — see error-log\n\n')" \
    "maintainer-fail-banner" 250
  if [ "$(sb_get_maintainer_fails "$slug")" -ge "$N_MAX_FAILS" ]; then
    touch "$DISABLED"
    sb_log_error "session-load.sh" "maintainer-auto-disabled slug=$slug fails=$N_MAX_FAILS" 0
  fi
fi

# 2. Decide this session's dispatch.
if [ "$AUTO" != "off" ] && [ ! -f "$DISABLED" ]; then
  COUNT=$(sb_get_wiki_writes "$slug")
  if [ "$COUNT" -ge "$N" ]; then
    sb_append "$(printf '%s' "$MAINTAINER_BANNER_TEMPLATE" | \
                  sed -e "s/<N>/$COUNT/g" -e "s/<slug>/$slug/g")" \
      "maintainer-auto-banner" 1400
    touch "$DISP"
    sb_log_error "session-load.sh" "maintainer-auto-dispatched slug=$slug count=$COUNT" 0
  fi
fi
```

`MAINTAINER_BANNER_TEMPLATE` is defined as a heredoc at the top of `session-load.sh` and contains the exact BLOCKING REQUIREMENT text from the design (see "additionalContext template" below). The `<KD>` placeholder is substituted with the resolved knowledge dir (`${CLAUDE_PLUGIN_OPTION_KNOWLEDGE_DIR:-$HOME/knowledge}`) in the same sed pass that fills `<N>` and `<slug>`.

## additionalContext template

Emitted by `session-load.sh` when threshold met. Stored as `MAINTAINER_BANNER_TEMPLATE` in the script.

```
## ⚙ BLOCKING REQUIREMENT — knowledge-maintainer auto-dispatch

Project `<slug>` has accumulated <N> wiki writes since the last
consolidation cycle. Before responding to the user's prompt, you MUST:

1. Dispatch the `second-brain:knowledge-maintainer` subagent via the
   Agent tool. Brief it with: "Auto-dispatched after <N> wiki writes.
   Run full 6-phase consolidation. Knowledge dir: <KD>.
   Brain dir: ~/.second-brain. Project slug: <slug>."

2. When the subagent returns, write this acknowledgment file to mark
   the run complete (counter reset depends on it):

       echo ok > ~/.second-brain/projects/<slug>/.maintainer-needed-last

3. Print ONE LINE to the user in this exact format, derived from the
   subagent's report:

       ✓ second-brain maintainer: R relations, D descriptions, B broken-links, O orphans

   Where R/D/B/O are integers parsed from the subagent's phase 3/4/1 totals.
   If the subagent reports zero changes in all phases, print:
       ✓ second-brain maintainer: nothing to consolidate

4. THEN respond to the user's actual prompt. Do not surface the full
   subagent report unless the user asks.

Override: set `SB_MAINTAINER_AUTO=off` in shell rc to disable this entirely.
```

## Configuration

| Env var | Default | Effect |
|---|---|---|
| `SB_MAINTAINER_AUTO` | `on` | `off` disables the auto-dispatch path entirely. State files still exist but are not read. |
| `SB_MAINTAINER_THRESHOLD` | `3` | Integer; minimum `.wiki-writes` count before next SessionStart auto-dispatches. |
| `SB_MAINTAINER_MAX_FAILS` | `3` | Consecutive failure count that triggers the per-project auto-disable marker. |

User-controlled state:
- `~/.second-brain/projects/<slug>/.maintainer-auto-disabled` — delete this file to re-arm auto-dispatch after the 3-strike limit has been hit.

Documented in `README.md` under the existing "Kill switches" section alongside `SB_PERSONA_GATE`, `SB_QUALITY_GATE`.

| 8 | old `.maintainer-needed` flag present (migration) | flag removed; counter set to threshold value; first SessionStart triggers |

- When a wiki page is written, `.wiki-writes` increments by 1.
- When no wiki write happens, counter unchanged.

## Migration

Single migration entry added to `skills/upgrade/SKILL.md` registry:

```
| 2.8.0 | Auto-dispatch knowledge-maintainer on wiki-write threshold.
  (a) New per-project counter ~/.second-brain/projects/<slug>/.wiki-writes
      incremented by merge-project-update.sh on wiki page writes.
  (b) New session-load.sh state machine: reads counter, manages
      .maintainer-dispatched + .maintainer-needed-last markers, emits
      blocking-requirement banner when count ≥ SB_MAINTAINER_THRESHOLD.
  (c) 3-strike auto-disable backstop via .maintainer-auto-disabled marker.
  | If `.maintainer-needed` exists for any project, set
    .wiki-writes = SB_MAINTAINER_THRESHOLD and remove the old flag.
    Idempotent — re-running when the old flag is absent is a no-op.
```

The migration script logic:

```bash
for d in ~/.second-brain/projects/*/; do
  slug=$(basename "$d")
  if [ -f "$d/.maintainer-needed" ]; then
    echo "${SB_MAINTAINER_THRESHOLD:-3}" > "$d/.wiki-writes"
    rm -f "$d/.maintainer-needed"
  fi
done
```

## Risks

| Risk | Severity | Mitigation |
|---|---|---|
| Parent Claude ignores the BLOCKING REQUIREMENT banner | low (existing banners are obeyed today) | counter doesn't reset → banner re-appears next session; self-correcting |
| Maintainer crashes repeatedly (auth broken) | medium | 3-strike auto-disable + error-log + user-visible banner |
| Counter file corrupted | low | defensive parse defaults to 0 |
| Banner pollutes context for trivial sessions | low | only emits at threshold; structured-response contract caps surface |
| User unaware that auto-disable hit | medium | failure banner on each detection; permanent visible marker file |
