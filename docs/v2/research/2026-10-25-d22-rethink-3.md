# V2-D22 rethink 3: the route after the first slice's eval

Written 2026-10-25, after build step 2d fired D22's triggers. Before any code or run for a new attempt. The evidence is
in [../06-first-slice.md](../06-first-slice.md) ("2d: result") and in D22's reopen note in
[../DECISIONS.md](../DECISIONS.md). A second opinion follows below.

## What the route is

At session start, an index of the repo's document files grouped by directory, under Vercel's retrieval-led line. At
the first prompt of each epoch, a forced decision: for each directory, does it bear on the task (yes or no); then read
the documents in every yes directory before changing anything.

## What held

- **Build and plan tasks in the repos whose rules live in prose (P1, P2).** Claude followed rules that native misses:
  - P2 build R4 to R7 (for example R7 7 against 1, R5 9 against 3);
  - P1 build R6 (10 against 0);
  - P2 plan P1, P4 and P5.
- On A1, the second person was served through the committed map.
- Total A2 cost was lower than native's (324.52 against 345.67).

## What did not, and why (counts from the 120 investigation streams)

- **The directory decision is too coarse for large directories.** Where a yes directory holds dozens of documents,
  Claude names a few on the yes line and reads 1 to 5. Two anchors were read once in ten (S2, C4). S2's matching
  lines even showed up in Grep without the file being opened.
- **A lone document next to dismissed directories is dismissed with them.** R0's A2 and A3 anchor is the only file in
  its directory. It was triaged out in every run, and Claude answered from code.
- **Some answers live in code.** S4's anchor is a code file. A document index cannot reach it, and native search did
  not reach it either.
- **Some misses are following, not selection.** S5 was read in full in 10 of 10 runs and passed in 2. R0 build's R6
  was read in every run of both arms and never applied. Those are D20's question.
- **Plan tasks pay for the forced read.** P2 plan read 6 documents against a ceiling of 4, and cost 0.46 against 0.38
  USD. It also followed P1, P4 and P5 far more often.

## The scope question (the user's; settled by this rethink and a second opinion, open to their override)

Are investigation tasks ("how does X work here", "what does the project say about Y") in v2's scope?

- *For:* the charter says Claude should "have and know where to find what the project already decided" in
  architecture, planning, coding and review. Answering a question about the project is that knowing.
- *Against:* the charter's main idea, and A1, are about Claude changing or creating a part with the project's decisions
  in hand. The six investigation tasks joined through D19's trigger, after the route was designed for build tasks.
- *Reading:* in scope, but as a different job. For a question, the route should help Claude *find* the one document
  that answers it. For a change, it should make Claude *read* what binds the change. One forced decision at directory
  level serves the second job, not the first.

## Options for the next attempt

- **(a) Keep the route, and narrow the claim.** v2 claims build and plan tasks only. Investigation tasks are recorded
  as native's ground, and D22's investigation clause is retired with a reason. Cheapest, but it gives up a job the
  charter names.
- **(b) A finer forced decision.** Keep the directory triage, and in any yes directory of more than about 10 documents,
  have Claude name the documents that bear on the task and read those. It changes D22's frozen forced text, so this is
  D22's next attempt. A little more output per session.
- **(c) A richer index:** each document's title (its first heading) beside its name, so a lone or large-directory
  document can be picked by topic. It costs always-on bytes: about 40 B per document, so P2 grows from 6 KB to about
  14 KB. D13's cap and D22's "index past 6 KB" trigger apply.
- **(d) Nudge on a document hit.** When Grep lists a document's lines, tell Claude to open it. That needs a fourth hook
  event, past the surface budget, and it helps one cell (S2).

## Proposal

**(b) first, (c) only if (b) fails.**

- (b) is a text change inside the existing surface. It targets the measured mechanism, a yes directory too large to
  read. It leaves the small-directory build tasks, where the route worked, alone.
- (c) costs every session bytes and is the larger change.
- Neither reaches S4 (code) or fixes S5 and R6 (following). Those are recorded as outside selection.
- **The check, before any run:** the six investigation tasks under (b), 10 runs each, against M1's thresholds. Each
  cell that M1 reaches stays at its bar, and the cells the mechanism names (A2, A3, S2, C4) must rise. The build and
  plan tasks re-run as a regression check: no rule cell falls below 2d's count.

## Second opinion (Gemini, Pro, 2026-10-25, given a condensed version of this note)

The clipboard was locked, so the text was typed into the page. It was public repo text.

- **Scope: narrow the claim.** Investigation is a "find the needle" search problem; build and plan is a "read the
  constraints" problem. A forced-read mechanism serves the second. Take the win on build and plan, and leave questions
  to ordinary search.
- **(b) is the wrong shape.** Choosing files in a large directory from bare names is guessing, not reasoning, and it
  does nothing for the lone document.
- **Its risk and change:** (b) adds load to the opening turn and could fail the regression check. If anything, take
  (c): titles in the index, with one simple directive to find and read the relevant documents, instead of directory
  triage.

## Decision, weighing both

- **The scope point is taken, for this slice.** The evidence supports it. One anchor is code, and one miss is
  following after a full read. Native does not reach these cells either, so a document index is not the instrument
  for them. v2's claim narrows to change and plan tasks, and the six investigation tasks are recorded as native's
  ground. *This is the user's call. It is settled here by rethink and second opinion, as the standing instruction
  says, and is open to their override.*
- **The route stays as it is.** The second opinion would replace the directory triage with titles and one directive.
  But D22's own history shows an index without a forced decision failing (arm `p`), and the forced decision is what
  produced the build and plan gains. Replacing it would risk the one result that holds. (c) is recorded as the
  candidate if investigation tasks come back into scope.
- **P2 plan's ceiling breach is recorded as a trade, not excused.** The forced read cost more there and bought rule
  following (P1, P4 and P5). D17's rule has no cell for that trade (a Fog line). The trigger fired, and the re-lock
  states the trade openly.
