browser extension was not connected), so a different Claude model reviewed the draft in a fresh context.

## What 2e showed

The trigger fired as written, and that stands: "a rule in scope is missed on a vague first prompt or in a session
with more than one compaction". It fired on P2 build's R4 and R5 (vague) and R6 (two compactions). Split by kind,
from the streams:

| Kind | Cells | What happened |
| --- | --- | --- |
| Selection | P2 R5, vague | The directory was marked yes at the symptom turn (5 of 5 runs). The document was never read in 4. The task's prompt, in turn 2, got no forced decision. |
| A read for an earlier task | P2 R5, task switch | The document was read during the first task, before the compaction. After it, the full decision came with "Now make the change", and the document was re-read in 2 runs (both passed), not in 3 (all failed). |
| Following | P2 R4 (vague and switch), R6 (two compactions) | Both come from the root instruction file, which Claude Code reloads after every compaction. The rule was in context and broken. |
| Nothing to apply to | R0, task switch | Two runs extended an existing script, and the checks look for a new one. |

## The assumption, one level up

D22's reopen note named it: *one yes/no decision per directory, made at the start of an epoch, selects what a later
change needs.* The first draft read the evidence as timing. The second opinion showed that one cell contradicts that
reading, so it is restated here.

- **What fits every cell: the decision selects well when the prompt at hand carries the change's terms.**
  - *Standard shape:* the first prompt is the task. P2 R5's document, in a directory of dozens of files, was read in
    the first turn in 9 of 10 runs.
  - *Vague shape:* the decision is made on a symptom. The task's terms arrive in turn 2, where no decision is made, and
    the document was read in 1 of 5.
  - *Task switch:* the decision after the compaction is made on "Now make the change", which carries no terms. They
    sit in the summary. The document was re-read in 2 of 5.
  - Timing alone does not explain the switch, where the decision did come at the change. The terms do.
- **Granularity: one decision covers a whole directory.** Within a large yes directory, Claude reads what the prompt's
  terms point to.
  - On investigation tasks (2d), that was 1 to 5 of dozens, and the anchor was missed.
  - In the user's own check it was 6 of 30 and 3 of 34, while small directories were read in full. Whether those
    samples missed anything is unmeasured.

How this reconciles with the reopen note ("goes up a level to that assumption, rather than rewording the forced
text"):
- The attempt leaves the decision itself unchanged.
- It adds a selection at the moment the change's terms arrive in a later prompt. This is the half of the assumption
  that ties selection to the epoch's first prompt.
- The cell where the terms never arrive in a prompt (the switch) is not addressed. It stays recorded under 04's
  friction weakness.
- Granularity stays recorded against investigation tasks (outside v2's claim since 2026-10-25).

## Options for the next attempt

- **(a) Narrow the claim again**, to changes requested in a session's first prompt. *Rejected:* a symptom first and
  the change second is ordinary use.
- **(b) The full forced decision at every prompt.** *Rejected:* on P2 that is about 45 lines of triage on every
  prompt, including the turns Claude Code starts itself when a background task finishes.
  - Verified in 2e's streams: the hook fires on those turns, right after a `task_notification`. The hooks reference
    says it "also fires on turns Claude Code starts on its own".
- **(c) A short forced read on every later prompt of an epoch, conditional on a change.** The epoch's first prompt keeps
  the full decision, unchanged. Every later prompt carries one fixed sentence: if the message asks for a change, name
  the documents from the yes directories that bind it, and read the unread ones before the first edit.
  - It stays inside the surface budget: the existing `UserPromptSubmit` hook, one more branch.
  - It demands an output when it applies.
- **(c') (c) with a search in place of naming:** Grep the yes directories for the change's terms, then read the hits.
  This is the second opinion's proposal. *Not now.* It changes two things at once. In 2d, Grep showed a document's
  lines without it being opened (S2). In the vague shape, the one run that met R5's document by Grep still failed.
  It is the next candidate if (c) fails on naming.
- **(d) A `PreToolUse` hook at an epoch's first write.** *Rejected:*
  - its added context arrives next to the tool's result, after the write (hooks reference);
  - a deny costs a rewrite, and D20 stage 2 found the pre-write deny fixed nothing that prompt-time delivery had not;
  - it is a fourth hook event, past the budget.
- **(e) Titles for large directories** (rethink 3's (c)). *Not now:* it is the granularity half. It stays the candidate
  for investigation tasks.

## Proposal: (c)

- **Text (frozen before any run, 255 bytes):** "If this message asks you to change or create something, then before
  your first edit for it: name in one line the documents from your yes directories that bind this change, and read the
  ones you have not read since the session start or the last compaction."
- **On the second opinion's objection** that this is rethink 3's rejected "choosing by bare name":
  - In the standard shape, Claude chose from the same bare names, with the task's terms in hand, and read R5's
    document 9 of 10 times. Naming fails when the terms are absent, which is the case (c) addresses.
  - The objection stands for investigation tasks, where that rejection was made.
- **Where it fires:** every `UserPromptSubmit` after the first of an epoch, only in a session that has an index. Per
  run, in the streams on record:
  - 0 in A1's 70 v2 sessions, in P1's and R0's standard build runs, in P2 plan and in R0-buddy;
  - 0 to 3 in P2 build's standard runs, all self-started;
  - 0 to 5 in the other investigation tasks, all self-started;
  - the vague shape's turn 2 and the switch's build investigation turn, plus self-started turns.
- **Budget:** 06's "227 B at most once per epoch" gains "plus 255 B on each later prompt", a D18 budget line,
  disclosed. The always-on bytes per session are unchanged.
- **A changed plugin is a new hash.** If the attempt passes, these are not re-run:
  - A1, P1 and R0 standard, P2 plan and R0-buddy: there was no later prompt in an epoch on record, so the new branch
    did not fire. Their results carry over.
  - The investigation tasks, which do have self-started turns: they are outside v2's claim since 2026-10-25. Their
    recorded v2 numbers stay marked as the previous plugin's.
- **Known limit:** the fix is shown on one vague prompt per task (frozen at 2e). A second prompt would need its own
  baseline on the previous plugin.

## The check (pre-registered in DECISIONS.md before any run)

- **Stage 1, the fix:**
  - First, one Haiku smoke shows the text on the vague turn 2, and nothing on the first prompt.
  - Then P2 build in the vague shape: 5 runs.
  - *Pass:* R5 fails in at most 1 of 5, and its document is Read in the epoch of the first code write in at least 4
    of 5.
  - *Fail:* stop. Stage 2 does not run, and the fail path applies.
- **Stage 2, no loss and the R6 control:** 5 runs each:
  - vague: P1, R0;
  - task switch: P1, P2, R0;
  - standard: P2;
  - native two compactions: P2.
  - *No loss:* each rule in scope that held in the cell's reference fails in at most 1 of 5. The reference is 2e's
    same cell, or 2d's standard arm for P2 standard, and 05's listed misses are out of this set.
  - *R6:* native fails it in 2 or more of 5.
- **Recorded beside the scores:**
  - per run, whether the text arrived on every later prompt (a run is valid only if so);
  - in the vague runs, what Claude named on the text's line, and whether R5's document was among the names;
  - cost against 2e's medians, and P2 standard against M1's no-worse ceiling (D22's first trigger applies as before).
- **Pass:** stage 1, no loss, and R6 listed by the native control. D22 is then re-locked on (c).
- **Fail:** any of the three. D22 goes BLOCKED, and the assumption reopens (the reopen note).

## Second opinion (a different Claude model, fresh context, 2026-10-26)

It was given the draft, 06's 2e result, D22's last two records, the process rules and the plugin's code, and told to
attack. Its points, and what was done with each:

- **The switch cell contradicts the timing reading:** the decision came at the change there, and the read still did
  not happen in 3 of 5. *Taken.* The reading is restated as "the prompt at hand carries the change's terms", which
  fits every cell.
- **(c) relocates the rejected "choosing by bare name", and "the ones that bind" softens "every document".** *Partly
  taken.* Bare names worked with the terms in hand (standard, 9 of 10), and that is the case (c) creates. The search
  variant is recorded as (c'), the next candidate.
- **That the hook fires on self-started turns was unverified.** *Not taken:* it is verified in 2e's streams and in the
  hooks reference.
- **(c) never fires in the two-compaction and standard shapes, except on self-started turns.** *Taken in part.* The
  new-plugin two-compaction arm is dropped. P2 standard stays, since self-started turns are where the text could cost
  something. The native control stays, now as a pass condition.
- **Re-homing the following misses by narrowing the trigger is a rule 2 move, and "reported, not scored" left a
  loophole for R6.** *Taken.* The trigger keeps its text. Following misses go on the expected-miss list only with
  native evidence, and R6's control is a pass condition.
- **Run the vague P2 cell first.** *Taken* (stage 1).
- **Record what Claude names, fix the time clause, guard the empty index.** *Taken:* the text says "since the session
  start or the last compaction", and the code emits it only in a session whose index opened an epoch.
- **"No loss at most 1 of 5" across about 50 rule-cells lets a one-run regression everywhere pass.** *Noted, not
  changed:* it is D20's held rule, the bar every earlier cell was scored by.

## Second opinion, Gemini (2026-10-26, asked once the browser reconnected)

It was given a condensed version of this note: the findings, the reading, the proposal with its exact text, the
rejected options and the staged check. That is public repo text, typed into the page.
- Gemini Pro was "in high demand", so Gemini Flash answered.
- The first try failed ("something went wrong"). The reply that came back followed a "try again" message that this
  session did not send.

Its points, and what was done with each:
- **The cause is "premature commitment and gate disconnection".** The turn-1 triage is treated as done, so the
  specific change in turn 2 is written without being re-gated. *Consistent with the restated reading:* (c) adds that
  gate at the later prompt.
- **(c) can fail silently.** The model may judge turn 2 an incremental step, or name no binding document, to save
  tool calls. *Taken as a risk to watch:* stage 1 records, per vague run, what Claude names on the text's line and
  whether R5's document is among the names.
- **"Read in the epoch of the first code write" does not prove the read came before the edit was planned.** *Taken.*
  The fix bar now requires the read before that first write, not merely in its epoch. This was registered while
  stage 1 ran and before any of its output was read, and it makes the bar stricter.
- **Listing the following misses hides plugin failure behind native's weakness,** since the plugin's value is
  compliance where native fails. *Not taken as a change to the check, but given a consequence.*
  - The expected-miss list is the plan's pre-registered mechanism, and listing requires native evidence.
  - But the standard-shape gain on these rules (v2 10 of 10, native 6 and 7) is then not claimed outside the standard
    shape. No release text may claim R4 or R6 gains in long or vague sessions.
  - Two reviewers raised this point independently, which is why it gets a binding consequence.
- **5 runs and "at most 1 of 5" are weak statistics.** *Noted, not changed:* it is D20's rule, used for every cell so
  far. Changing it here would break comparison with them.
- **Its recommendation:** drop the per-prompt text, run an automatic keyword search when the edit target appears, and
  inject the documents deterministically through tool hooks right before edits. *Not taken now:*
  - prompt-time lexical selection failed twice (D13);
  - a pre-write deny fixed nothing that prompt-time delivery had not, and costs a rewrite (D20 stage 2);
  - a `PreToolUse` hook's added context arrives after the write.
  - The search half stays as candidate (c'), if (c) fails.
- *Provenance, corrected the same day (the user):* the browser was on an account without the intended Gemini model,
  which is the likely cause of the error and of the fallback to Flash. The review is kept as evidence from a weaker
  model than intended.

## Result (2026-10-26): stage 1 failed; D22 is BLOCKED
