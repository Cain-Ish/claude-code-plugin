# Migration to 0.24.47

## What changed

Fixed a family of wiki graph-pipeline bugs (user-reported). The graph→page
projector was emitting INVALID YAML frontmatter — the bracketless multi-item
form `related: [[a]], [[b]]` and orphaned block-list children — which the
plugin's own regex readers tolerated but a real YAML parser rejects (a live
scan found ~86% of pages affected). Also: edgeless pages kept stale
`related:`/`## Dependencies` forever (removing a node left its children
dangling); the projector re-emitted links to deleted pages; and FORGET
emitted zero candidates because its recency decay could never cross the
candidate floor.

Now: the projector emits canonical `related: [a, b]` (valid YAML), scrubs
edgeless pages to `related: []`, and filters edges to live page slugs;
`knowledge_validate --autofix` (run every reindex/maintain) detects and
normalizes malformed frontmatter; FORGET uses a 90-day recency window
(`SB_FORGET_RECENCY_DAYS`).

## Action / idempotent check

Heal already-corrupted pages by running ONE consolidation pass — the autofix
is idempotent and uncapped:

`/second-brain:reindex`  (or `/second-brain:maintain`)

This re-projects every edge-bearing page to the β form and normalizes any
remaining malformed frontmatter. Idempotent check: a second reindex reports
0 `malformed_frontmatter` issues and 0 pages updated. No frontmatter FIELDS
are deleted (title/type/tags/etc. preserved) — `related:` is re-derived from
`graph/edges.jsonl` (the documented source of truth: it is projected, never
hand-authored), and normalization only re-serializes `related:`/`tags:` and
drops orphaned block-list lines that were never valid YAML. If you enabled the
graph WITHOUT running the one-time importer (`graph-migrate.sh`, migration
0.22.0), seed it first so hand-authored `related:` links become edges before
they are re-derived.
