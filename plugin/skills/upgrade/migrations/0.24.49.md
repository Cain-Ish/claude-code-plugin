# Migration to 0.24.49

## What changed

Fixed three interaction bugs (deep-review P1/P2/P3) that made reindex
NON-idempotent on a graph-enabled wiki — the projector, the validator, and
parseDoc disagreed on what "no relations" looks like in bytes:
- parseDoc treated an explicit `related: []` like a missing key and re-filled
  it from body `[[links]]` → false `related_drift` + phantom search boosts on
  every page the projector just cleaned. Now `related: []` is authoritative
  (scrape only when the key is absent).
- patchFrontmatter body-derived `related:` while the projector wanted `[]` →
  they oscillated every reindex. Now on a graph-enabled corpus patch emits
  `related: []` (the projector is the sole writer).
- orphan-GC skipped edgeless pages carrying a legacy block-list `related:` →
  stale/dead links survived forever. Now any non-empty `related:` shape is
  admitted and collapsed to `[]`.
Also: a duplicate `sb_validate_wiki` in lib.sh (shipped 0.24.48) shadowed the
count-returning one; deleted. Added js-yaml (dev-only, never bundled) + a
parse-validity release gate so invalid-YAML frontmatter can never ship again.

## Action / idempotent check

Run ONE reindex to converge any pages still carrying a body-derived related:
or a stale block-list:

`/second-brain:reindex`

Idempotent check: a second reindex reports 0 pages updated and the wiki's
frontmatter all parses as valid YAML. No data deleted — `related:` is
re-derived from the edge graph (its source of truth).
