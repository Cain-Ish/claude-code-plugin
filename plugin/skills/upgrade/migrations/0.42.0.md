# 0.42.0 — the offline engine (brain-os)

No action required. Everything below is on by default and reversible; this note exists so
you recognise what appears on disk and know how to switch any of it off.

## What changed

The out-of-band passes that used to sit inline in the drainer now run behind one named seam,
`scripts/brain-os-run.sh`, invoked once per drainer tick. Same schedule, same single-flight
lock — one boundary you can point at, gate and disable.

New in that lane:

- **An embedding warm pass.** Wiki vectors are precomputed on the drainer timer, so the first
  search of a session no longer pays to embed pages that changed since you last searched.
- **A reversibility window.** Every unattended write is snapshotted into a git history, so any
  consolidation can be inspected and undone later.
- **Relation building.** The consolidation lane now proposes graph edges from what it distils,
  restricted to `relates` and applied through the existing endpoint-guarded edge writer.

## New files you will see

| Path | What it is | Safe to delete? |
|---|---|---|
| `~/.second-brain/wiki-history.git` | The wiki's snapshot history. A **detached** git dir — no `.git` is created inside your knowledge dir, so Obsidian and cloud sync are unaffected. | Yes — you lose the undo history, nothing else. |
| `~/.second-brain/held-untrusted/<dream>/` | Pages the consolidation lane distilled from transcripts that no existing page corroborates. Held, never applied, never deleted. | Yes, if you don't want them. They are copies, not moves out of your wiki. |
| `<knowledge>/graph/edges-quarantine.jsonl` | Proposed edges whose endpoints don't resolve yet. Replayed automatically once they do; dropped after 30 days if they never do. | Yes — regenerable. |

## Held pages: the one thing that wants your attention

If SessionStart tells you pages are HELD, that is the accept gate doing its job: a page
distilled purely from transcripts, with nothing in your wiki vouching for it, is exactly what a
poisoned transcript could invent. Review them under `~/.second-brain/held-untrusted/`, then
either delete the directory or release a dream's worth:

```bash
SB_DREAM_ACCEPT_CONFIRM_UNTRUSTED=1 bash scripts/dream-accept.sh <dream_id>
```

Release skips any slug a real page has taken since, and never writes through a symlink.

## Undoing a consolidation

```bash
bash scripts/wiki-history.sh list          # recent snapshots
bash scripts/wiki-history.sh show <ref>    # what that one changed
bash scripts/wiki-history.sh restore <ref> # bring its pages back (add --exact to also
                                           # remove pages created since)
```

A restore snapshots the current state first, so the undo is itself undoable.

## Switching things off

| Key in `~/.second-brain/config.json` | Effect when `false` |
|---|---|
| `brain_os` | Disables the whole offline lane. Capture and retrieval are untouched; consolidate in-session with `/second-brain:maintain` and `/second-brain:dream`. |
| `auto_embed` | No offline embedding warm pass. |
| `wiki_git` | No snapshot history (you keep the per-accept tarball). |

Env kill switches for a single run: `SB_BRAIN_OS=off`, `SB_WIKI_GIT=off`, `SB_HELD_BANNER=off`.

**Existing installs:** `config.json` is never clobbered on upgrade, so these keys will not
appear in yours. Absent means the built-in default, which is on — add a key explicitly to
change it.

## One behaviour change worth knowing

`auto_accept: "safe"` now **accepts** dreams containing untrusted-derived pages instead of
refusing them, because the accept gate holds those pages individually. Refusing the whole dream
left an unreviewed dream every cycle and would have halted consolidation entirely within days.
Nothing untrusted reaches your wiki unattended either way — the protection moved from "refuse
everything" to "hold the specific pages", which is both safer and keeps the lane running.
