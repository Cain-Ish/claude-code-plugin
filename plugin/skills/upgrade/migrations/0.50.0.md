# 0.50.0 — registration guard for $HOME / temp roots

No action required. This runs automatically the next time `ensure-dirs.sh` fires
(SessionStart, or the next drainer tick) and is one-time and idempotent.

## What changed

Opening `claude` directly at `$HOME` or a bare temp root (`$TMPDIR`, `/tmp`,
`AppData/Local/Temp`, a `mktemp` dir) used to register that directory as an ordinary
project. If it later became the registry's most-recently-active row, `brain-os-run.sh`'s
out-of-band code-map pass would crawl the **whole home directory** — one live install
produced a 9.6MB `graph.json` naming browser-extension bundles under
`AppData/Local/BraveSoftware/...` as "architectural spine".

`session-load.sh` now refuses to register (or hand to the code-mapper) a root that is
`$HOME`, a temp root, or has neither a `.git` nor a workspace manifest of its own — such
a session falls back to the same shared `scratch` project slug that mktemp-style working
directories already collapse into. `brain-os-run.sh` carries the same check as a second
line of defense for `SB_CODEMAP_REPO` overrides and pre-existing registry rows.

## One-time cleanup

The first `ensure-dirs.sh` run after upgrading sweeps `~/.second-brain/projects.jsonl`
for any row registered before this guard existed whose `root_path` is `$HOME` or a bare
temp root. Matching rows are removed from the live registry — but never silently: they
are appended first to a dated sidecar,
`~/.second-brain/projects.jsonl.purged-<YYYYMMDD>`, so you can see exactly what was
pulled and why. A marker file (`~/.second-brain/.ensure-dirs-d118-purge-done`) makes the
sweep run only once; delete it if you ever want the sweep to re-run (harmless — it is a
no-op once nothing matches).

If you had a real project deliberately rooted at `$HOME` or inside a temp directory (for
example a dotfiles repo with its own `.git`), it is unaffected — the guard only refuses
roots that carry no project marker of their own.
