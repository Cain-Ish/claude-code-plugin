# 0.55.0 — memory goes to the prompts you type, not to machine turns

Nothing to do. Read the two notes below if you run `claude -p` yourself.

## What changed

- **Machine turns no longer get memory.** These turns used to get wiki hits, "past sessions" and a
  `[buddy:]` line just like a typed prompt (68% of all injections went to them):
  - background-task notifications (`<task-notification>`);
  - subagent hand-backs ("Another Claude session sent a message:");
  - Stop-hook feedback;
  - harness tags such as `<system-reminder>`;
  - an exact repeat of your previous prompt (cron check-ins).

  Now they get none. `SB_MACHINE_TURN_SKIP=off` restores the old behaviour.
- **Headless children get no memory by default.** A `claude -p` run that second brain did not spawn
  itself no longer receives the session card, per-prompt memory, Stop extraction or plugin discovery,
  for example another plugin's summarizer. Such a run is detected by `CLAUDE_CODE_SESSION_ATTENDED=0`
  or `CLAUDE_CODE_ENTRYPOINT=sdk-cli`. PreToolUse safety guards still run.
- **Episodic recall is re-parsed once.** Machine-initiated exchanges keep their row and the assistant
  side. Their user side is cleaned: notification boilerplate is blanked, and a hand-back keeps its
  report body without the wrapper. "Past sessions" no longer offers task-notification text, and no
  longer offers your current session.
  - The re-parse runs in the background on the next Stop or PreCompact.
  - Only the cleaned rows (about half on a busy install) are re-embedded once.
  - The archives on disk are untouched.
- **Wiki hits must be grounded in your prompt.** Generic words such as "check", "commit" and
  "changes" no longer count. Single letters no longer count; numbers still do ("season 8").
  "Auto-created stub" pages are never offered. A page from another project needs one more matching
  term.

## If an older Claude Code session is still running

Close sessions that started before the upgrade once the upgrade is done. An old session's Stop hook
still runs the old indexer, which writes the pre-0.55 index format. The next new session then
re-parses those files again and re-embeds the cleaned rows a second time. That costs CPU, not data,
and it stops once every session runs 0.55.0.

## If you run `claude -p` yourself and want memory in it

```
SB_HEADLESS_CONTEXT=on claude -p "…"
```

Leave it unset for automation that should run lean. Interactive sessions are unaffected.
