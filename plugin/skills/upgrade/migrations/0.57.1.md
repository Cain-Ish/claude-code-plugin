# 0.57.1 — guards see every Windows alias, a later dream keeps an earlier one's pages

Restart Claude Code sessions that are still open. One action for some Linux installs (below).

## Look at once

1. **Linux, scheduled drainer, custom `BRAIN_DIR` or `CLAUDE_CONFIG_DIR`:** re-run
   `bash "$CLAUDE_PLUGIN_ROOT/scripts/install-extract-timer.sh" --apply` (add `--oauth` if installed that
   way). The unit written by 0.57.0 did not grant those dirs write access, so the drainer could not
   lock or write there and drained nothing. `--ensure` (and the session-start self-heal) leaves an
   existing unit alone, so only `--apply` rewrites it. Paths holding `"`, `\` or `%` are now refused.
2. **Windows: more file writes ask.** A Write or Edit whose target uses NTFS stream syntax (a `:` past
   the drive letter, e.g. `x.md::$DATA` or `x.txt:Zone.Identifier`) or an 8.3 short name (`PERSON~1.JSO`)
   of a protected file now asks instead of passing unchecked.
3. **Learned warn rules start counting again.** A rule candidate now arms only after it was seen in 3
   different sessions with a message that passes the injection check; pending candidates stored by
   earlier versions restart at zero sessions.
4. **`/?` and persona_think** need `ANTHROPIC_API_KEY` inside a session; with a subscription login they
   now say so instead of returning nothing.
