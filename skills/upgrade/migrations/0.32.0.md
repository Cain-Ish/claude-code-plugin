# 0.32.0 — migration notes

Marker-bump release with NO automatic data migration: all state files are backward-compatible
and no script touches your data. Three behavior changes have a user-facing implication:

## Persona-card is no longer injected (per-prompt AND SessionStart)

The injection of `~/.second-brain/persona-card.md` was removed — it was a ~95% paraphrase of
`USER.md` re-sent every prompt (~330 tokens of waste). Your identity now loads ONCE per session
via `USER.md` (still force-emitted at SessionStart). The card file is still seeded and still
summarized by `persona_stats`; it is simply no longer injected. Nothing is deleted.

OPTIONAL ACTION — only if you hand-edited persona-card.md with bullets NOT in USER.md, fold them
into USER.md so they stay in your working context:

    diff <(grep '^- ' ~/.second-brain/persona-card.md | sed 's/^- *//' | sort -u) \
         <(grep '^- ' ~/.second-brain/USER.md        | sed 's/^- *//' | sort -u)
    # lines marked "<" are card-only — copy the ones you want into USER.md.

## persona_dismiss now does something (was a phantom)

It previously only logged. It now wires real backoff: after `SB_PERSONA_DISMISS_MAX` (default 3)
dismissals in the trailing `SB_PERSONA_DISMISS_WINDOW_DAYS` (default 7) window, persona-context.sh
self-suppresses the per-prompt ambient injection. Explicit `/?` Opus briefs are unaffected. No action.

## MCP knowledge-base 2.8.2 -> 2.9.0

- `knowledge_validate` now defaults to `autofix:false` (report-only); pass `{autofix:true}` to
  mutate. Internal automation already passes it explicitly, so nothing changes there.
- Destructive MCP write-tools (dream_*, pin_*, archive_to_wiki, knowledge_reindex/validate/relate,
  persona_dismiss) now REFUSE under `SB_NESTED_SPAWN=1` so a headless/nested spawn can't mutate the
  live wiki/dream state/PROJECT.md/USER.md unattended over untrusted content. No action.
