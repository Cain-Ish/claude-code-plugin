# 0.51.0 — the buddy, and a shipped tree that no longer carries the dev repo

No action required. Two things are worth knowing.

## The install now receives `plugin/` only

`marketplace.json` points at `./plugin` — a generated tree with hooks, skills, agents, scripts,
the compiled MCP server and manifests (~4.5 MB) instead of the whole repository (~8 MB with
tests, docs, sources). Nothing changes on disk for you: the plugin cache layout
(`~/.claude/plugins/cache/<marketplace>/second-brain/<version>/`) is the same, every shim that
resolves the newest version (`sb-extract-drain`, the buddy statusline) keeps working, and
`${CLAUDE_PLUGIN_ROOT}` still points at a directory with `scripts/`, `mcp/dist/`, `bin/` inside.
If you had scripted a path into the old tree's `tests/` or `docs/`, those are now only in the
repository.

## The buddy (opt-in)

A statusline layer between Claude and the knowledge base: it shows when memory is delivered,
offered, read (`knowledge_*`, `episodic_*`), saved (`pin_*`, `archive_to_wiki`, extraction),
which gate is holding, and what waits on you; it nudges Claude once per session to pin a
decision when nothing was saved. Zero tokens on the statusline. To turn it on:

```
/second-brain:buddy install        # or: sb buddy install
```

then restart Claude Code. It writes `~/.claude/settings.json`'s `statusLine` (backup taken, an
existing statusline is chained as line 1) and a shim at `~/.second-brain/bin/buddy-statusline.sh`.
Undo with `/second-brain:buddy uninstall`. Without `install`, nothing is displayed; the hooks
still write their small `.buddy/` state files (7-day TTL) unless `SB_BUDDY=off`.
