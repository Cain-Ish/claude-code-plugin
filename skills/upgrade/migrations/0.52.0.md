# 0.52.0 — linked worktrees now share the main checkout's brain

No action required for most repos. Read "Linked worktrees share the main repo's project"
below if you use `git worktree` — it can orphan an existing per-worktree brain.

## Linked worktrees share the main repo's project

A `git worktree`'s project slug used to be the worktree's own directory basename — a
repo checked out at `myrepo` with a worktree added at `../myrepo-feature` got TWO
separate brains, `projects/myrepo/` and `projects/myrepo-feature/`, with no memory
shared between them.

As of this release, a linked worktree's slug resolves against its MAIN checkout
instead (the git common-dir's parent), matching the pre-existing `git worktree`-aware
resolution the bash side (`sb_repo_key`) already had — the two resolvers had drifted
apart and are now locked in step. Every worktree of one repo now shares a single
`projects/<main-checkout-basename>/` brain: one `PROJECT.md`, one `rules.json`, one
learned-rules set, one Plan/Handoff.

**Who is affected**: a remote-less repo (or one whose remote isn't yet registered) that
already had projects registered under a WORKTREE's own basename — i.e. you were
running sessions from inside a linked worktree before this release and it had
accumulated its own `PROJECT.md` (Plan, Handoff, decisions) or `rules.json` separate
from the main checkout's. A repo with a registered remote is unaffected: remote
identity already outranked the basename, so its slug did not change.

**Check whether you're affected**:
```
ls ~/.second-brain/projects/ | grep <worktree-basename>
```
If that lists a directory matching one of your worktrees' own folder names (not your
main checkout's), it holds state this release no longer reaches — new sessions from
that worktree now resolve to the main checkout's slug instead, and the old directory's
content just sits there unread.

**Merge the orphaned state by hand** (nothing does this automatically — it is a
one-time manual step per affected worktree):
1. Open `~/.second-brain/projects/<worktree-basename>/PROJECT.md` and copy any Plan,
   Handoff, `## Decisions`, or other content worth keeping into
   `~/.second-brain/projects/<main-checkout-basename>/PROJECT.md`.
2. Open `~/.second-brain/projects/<worktree-basename>/rules.json` (if present) and
   merge its `.rules[]`/`.learned[]` entries into
   `~/.second-brain/projects/<main-checkout-basename>/rules.json` (`/second-brain:rules
   promote` can move an individual rule; for a bulk merge, hand-edit with `jq`).
3. Remove the now-redundant `~/.second-brain/projects/<worktree-basename>/` directory.

**Kill switch**: `SB_REPO_KEY_COMMON_DIR=off` restores the pre-change behavior (each
worktree keyed on its own directory basename) on both the bash and TS resolvers, if you
need to keep worktree brains separate.
