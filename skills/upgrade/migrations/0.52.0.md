# 0.52.0 — repo brain: the working agreement, delivered from the knowledge base

No action is required for most repos. If you use `git worktree`, read "Linked worktrees share the
main repo's project" below: this release can orphan an existing per-worktree brain.

Design and evidence: `docs/plans/2026-09-24-repo-brain.md`. Constitution: memory has a fifth
class, the **working agreement** (hard rules, conventions, work protocol), and the knowledge base
is its only home. Nothing is written into `.claude/rules`, `CLAUDE.md` or native `MEMORY.md`.

## What changes in a session

- **Protocol card at SessionStart.** A card of up to 1.2 KB states the work protocol: think before
  implementing, search before creating, verify before claiming done, and which model tier a job
  belongs to (tiers resolved from `model-ladder.json`). Off: `SB_PROTOCOL_CARD=off`.
- **Delegation check (warn-only).** Every `Agent` dispatch is checked against its job class, and a
  mismatch adds a warning to the context, for example a scouting job sent to the deep tier or a
  design job sent to the fast tier. Nothing is blocked. Every call writes a `gate=delegation`
  audit row. Off: `SB_DELEGATION_CHECK=off`.
- **Opt-in model rewrite.** `SB_DELEGATION_REWRITE=1` (default `0`) sets the Agent call's `model`
  for you through PreToolUse `updatedInput`. Doing so approves that Agent call without a prompt;
  deny/ask verdicts from other guards still win. Leave it off unless you want that.
- **Role cards for subagents.** A `SubagentStart` hook (the tenth hook event) gives Explore,
  general-purpose and custom agents a short SCOUT/DO/THINK role card plus the repo's hard rules.
  Plan subagents cannot receive hook context (verified live), so the delegation check tells the
  parent to put the rules into the Plan prompt instead. Off: `SB_ROLE_CARDS=off`.
- **Repo card replaces the forced PROJECT.md block.** SessionStart now injects a budgeted repo
  card (≤1800 B: direction, hard rules, active decisions, conventions) instead of up to 3000 B of
  raw `PROJECT.md`. Previous behaviour: `SB_REPO_CARD=off`.
- **Just-in-time delivery.** The first `Read`/`Edit` of a path that a wiki lesson, convention or
  decision names brings that item into context once per session, from a per-repo `jit-index.json`
  built from the KB. Up to `SB_JIT_MAX_ITEMS` (default 3) items per call. Off: `SB_JIT=off`.
- **Search before create (warn-only).** Writing a new source file whose name matches an existing
  file or symbol adds a warning that names the candidates. Off: `SB_SEARCH_FIRST=off`.
- **Master switch.** `SB_PROTOCOL_GUARD=off` disables all of the above protocol-guard behaviour, and
  `SB_HOOK_PROFILE=minimal` also turns it off.

## PROJECT.md and rules

- `PROJECT.md` gains `## Direction` (goal, non-goals, priorities "through YYYY-MM-DD") and
  `## Conventions`. New projects get both sections in the scaffold. Existing files can add them by
  hand, or let `pin_to_project(section: "conventions")` create the Conventions section.
- **Layered rules.** Effective rules = plugin defaults → your `persona-rules.json` → a per-repo
  `projects/<slug>/rules.json`. A default rule marked `lock: true` can only be tightened. The repo
  layer may add or raise `warn|ask|deny` rules; it can never add a `rewrite`, disable a rule, or
  lower an action. Off (single-file behaviour): `SB_RULES_LAYERS=off`.
- **`/second-brain:audit` is now `/second-brain:rules`.** It adds `show` (rules by layer, with
  provenance), `distill`, `promote` and `demote`; the old audit view is `rules audit`. Learned-rule
  candidates are now counted per repo.

## Telemetry format

`gate=value-loop` rows are now cumulative, one per Stop, and gain `ritual= pulled= agents= tiers=
turn= sid=` after `hits=`. The session total is the **last row per sid**. The project-anchor fetch
is reported as `ritual=`, never as a read. See `docs/daily-prompt.md` for the extraction command.

## Linked worktrees share the main repo's project

A `git worktree`'s project slug used to be the worktree's own directory basename — a
repo checked out at `myrepo` with a worktree added at `../myrepo-feature` got TWO
separate brains, `projects/myrepo/` and `projects/myrepo-feature/`, with no memory
shared between them.

As of this release, a linked worktree's slug resolves against its MAIN checkout
instead (the git common-dir's parent), matching the pre-existing `git worktree`-aware
resolution the bash side (`sb_repo_key`) already had — the two resolvers had drifted
apart and are now locked in step. Every worktree of one repo now shares a single
`projects/<main-checkout-basename>/` brain: one `PROJECT.md`, one `rules.json`, one
learned-rules set, one Plan/Handoff.

**Who is affected**: a remote-less repo (or one whose remote isn't yet registered) that
already had projects registered under a WORKTREE's own basename — i.e. you were
running sessions from inside a linked worktree before this release and it had
accumulated its own `PROJECT.md` (Plan, Handoff, decisions) or `rules.json` separate
from the main checkout's. A repo with a registered remote is unaffected: remote
identity already outranked the basename, so its slug did not change.

**Check whether you're affected**:
```
ls ~/.second-brain/projects/ | grep <worktree-basename>
```
If that lists a directory matching one of your worktrees' own folder names (not your
main checkout's), it holds state this release no longer reaches — new sessions from
that worktree now resolve to the main checkout's slug instead, and the old directory's
content just sits there unread.

**Merge the orphaned state by hand** (nothing does this automatically — it is a
one-time manual step per affected worktree):
1. Open `~/.second-brain/projects/<worktree-basename>/PROJECT.md` and copy any Plan,
   Handoff, `## Decisions`, or other content worth keeping into
   `~/.second-brain/projects/<main-checkout-basename>/PROJECT.md`.
2. Open `~/.second-brain/projects/<worktree-basename>/rules.json` (if present) and
   merge its `.rules[]`/`.learned[]` entries into
   `~/.second-brain/projects/<main-checkout-basename>/rules.json` (`/second-brain:rules
   promote` can move an individual rule; for a bulk merge, hand-edit with `jq`).
3. Remove the now-redundant `~/.second-brain/projects/<worktree-basename>/` directory.

**Kill switch**: `SB_REPO_KEY_COMMON_DIR=off` restores the pre-change behavior (each
worktree keyed on its own directory basename) on both the bash and TS resolvers, if you
need to keep worktree brains separate.
