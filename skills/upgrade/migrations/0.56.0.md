# 0.56.0 — nothing captured is lost

Nothing to do. Restart Claude Code sessions that are still open (last section).

## What changed

- **Every window is archived first.** Stop and PreCompact copy the new part of the transcript into
  `~/.second-brain/transcripts/` before anything else runs, including windows with no tool use.
  They used to be skipped. The position is kept in `.last-archived-line-<slug>--<session>`.
- **Credential formats are redacted in the archive.** Anthropic, OpenAI, GitHub, AWS, Slack and
  Bearer tokens and PEM private-key blocks become `[redacted:<kind>]`. OpenAI keys covered are
  `sk-` and the newer `sk-proj-`, `sk-svcacct-` and `sk-admin-` forms. Subagent results are scrubbed
  before they are archived too. Line counts never change.
  Passwords, short codes and generic high-entropy strings are not matched.
- **Higher archive caps.** 400 files / 25 MB (was 100 / 5 MB), hard ceiling 1200 files / 75 MB
  (was 300 / 15 MB); `sub-*` subagent results 200 (was 50). Archives that were already extracted
  go first. `SB_TRANSCRIPT_CAP`, `SB_TRANSCRIPT_HARD_CAP`, `SB_TRANSCRIPT_MAX_BYTES`,
  `SB_TRANSCRIPT_MAX_BYTES_HARD` and `SB_SUBAGENT_ARCHIVE_CAP` override them.
- **The drainer extracts only new lines.** The done-set (`.extraction-state.jsonl`) rows now carry a
  line window (`from`, `lines`) and a new outcome, `baseline`. An archive that grew since its last
  extraction is mined from where it stopped, not skipped and not redone. A live archive is taken
  once `SB_DRAIN_DELTA_MIN_BYTES` (4096) of new lines exist, or after it has been quiet
  `SB_DRAIN_QUIET_S` (3600 s).
- **Backlog counts come from one place.** The session banners, the dead-letter count and
  `sb-health-snapshot.sh` read the same per-archive cursor map, so a grown archive counts as pending
  again.
- **Smaller episodic index.** Vectors are stored as `e8` (int8, base64) plus a scale `es`, not
  float arrays: about 550 characters per row instead of about 8 KB.

## What happens on the first drainer tick

The first scheduled drainer run migrates your existing done-set. It makes no LLM call for this.

- An archive that was extracted and has not changed since gets a `baseline` row (reason
  `cursor-baseline`) at its current line count.
- An archive that was extracted and has grown since is re-mined from its start once, tagged
  `legacy-regrow`. The merge dedups what it already filed, so this costs a few extractor calls, not
  duplicate pages. Calls are limited to `SB_DRAIN_BATCH` per tick, so a large backlog drains over
  several ticks.
- An archive that was dead-lettered and has not changed stays dead-lettered (reason
  `legacy-dead-letter`). Only later growth is retried.
- The done-set rows of an archive whose file was recreated with fewer lines are dropped.

Existing archives are also scrubbed of credential formats once, in place, as part of this release.
The scrub keeps each file's modification time and line count and rewrites only files that contain
something to redact. It runs on the first drainer ticks, under the drain lock, at most
`SB_DRAIN_BATCH` archives per tick. The first tick lists the archives that need it in
`~/.second-brain/.archive-scrub-v1.todo`; when the list is empty `.archive-scrub-v1` is written and
it never runs again. An archive still on the list is not extracted until it is scrubbed, so a large
archive set delays extraction by a few ticks.

Old done-set rows stay valid; the new fields are additive.

## New state files

- `transcripts/.<archive>.lock`: a per-archive write lock. The Stop/PreCompact append and the scrub
  both take it (5 s wait; a lock older than 60 s is stolen). The drainer deletes leftovers older
  than a day.
- `.archive-scrub-v1` and `.archive-scrub-v1.todo`: the scrub migration marker and to-do list.
- `.last-archived-line-<slug>--<session>`: the archive cursor (above).

The ledger is also compacted every drainer tick: it keeps one row per archive cursor plus the
dead-letter and retry rows past it, and drops rows of archives that were evicted. Nothing the
drainer reads changes.

## Episodic index

The first index build after the upgrade converts old float rows to `e8`/`es` in place. Search never
rewrites the index. If you rebuild the index, a changed archive is re-parsed and a row whose text is
unchanged keeps its vector (no model call); only changed rows re-embed.

## If an older Claude Code session is still running

Close sessions that started before the upgrade once the upgrade is done. A running 0.55 MCP server
reads the old float format and errors on `episodic_search` once the index holds `e8` rows, until the
session is restarted. An old session's Stop hook also still archives the old way: it appends without the archive lock
and without scrubbing subagent results. The scrub re-checks the file size before it renames, so a
lost append is unlikely, but it is possible. Restart open sessions.
