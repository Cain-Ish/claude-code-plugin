# 0.56.0 — nothing captured is lost

Nothing to do. Restart Claude Code sessions that are still open (last section).

## What changed

- **Every window is archived first.** Stop and PreCompact copy the new part of the transcript into
  `~/.second-brain/transcripts/` before anything else runs, including windows with no tool use.
  They used to be skipped. The position is kept in `.last-archived-line-<slug>--<session>`.
- **Credential formats are redacted.** Matches become `[redacted:<kind>]`: Anthropic, OpenAI
  (`sk-`, `sk-proj-`, `sk-svcacct-`, `sk-admin-`), OpenRouter, Stripe, GitHub (`github_pat_`,
  `gh[opsur]_`), GitLab, npm, Hugging Face, Google (`AIza`), Slack, AWS (access key ids, and secret
  keys after their `aws_secret_access_key` keyword), JWTs, Bearer tokens (any case), `Authorization:
  Basic` values, and PEM/PGP private-key blocks. Zero-width characters are stripped first. Line
  counts never change. Not matched: passwords, short one-time codes, generic high-entropy strings,
  a bare AWS secret without its keyword.
- **Where the scrub applies.** Every archived window, subagent results (before they are quoted;
  a repeat stop for the same agent appends), the observations ledger (when written and again
  before it goes to the extractor), the transcript copies a dream stages, and every extraction: an
  archive holding a credential is scrubbed first, which also covers archives that a still-running
  0.55 session appended.
- **Higher archive caps.** 400 files / 25 MB (was 100 / 5 MB), hard ceiling 1200 files / 75 MB
  (was 300 / 15 MB); `sub-*` subagent results 200 (was 50). Archives that were already extracted
  go first. `SB_TRANSCRIPT_CAP`, `SB_TRANSCRIPT_HARD_CAP`, `SB_TRANSCRIPT_MAX_BYTES`,
  `SB_TRANSCRIPT_MAX_BYTES_HARD` and `SB_SUBAGENT_ARCHIVE_CAP` override them.
- **The drainer extracts only new lines.** The done-set (`.extraction-state.jsonl`) rows now carry a
  line window (`from`, `lines`) and a new outcome, `baseline`. An archive that grew since its last
  extraction is mined from where it stopped, not skipped and not redone. A live archive is taken
  once `SB_DRAIN_DELTA_MIN_BYTES` (4096) of new lines exist, or after it has been quiet
  `SB_DRAIN_QUIET_S` (3600 s).
- **Backlog counts come from one place.** The session banners, the dead-letter count and
  `sb-health-snapshot.sh` read the same per-archive cursor map, so a grown archive counts as pending
  again.
- **Smaller episodic index.** Vectors are stored as `e8` (int8, base64) plus a scale `es`, not
  float arrays: about 550 characters per row instead of about 8 KB.

## What happens on the first drainer tick

The first scheduled drainer run migrates your existing done-set. It makes no LLM call for this.

- An archive that was extracted and has not changed since gets a `baseline` row (reason
  `cursor-baseline`) at its current line count.
- An archive that was extracted and has grown since is re-mined from its start once, tagged
  `legacy-regrow`. The merge dedups what it already filed, so this costs a few extractor calls, not
  duplicate pages. Calls are limited to `SB_DRAIN_BATCH` per tick, so a large backlog drains over
  several ticks.
- An archive that was dead-lettered and has not changed stays dead-lettered (reason
  `legacy-dead-letter`). Only later growth is retried.
- The done-set rows of an archive whose file was recreated with fewer lines are dropped.

Existing archives and the transcript copies inside dream folders are also scrubbed once, in place.
The scrub keeps each file's modification time and line count and rewrites only files that contain
something to redact. It runs under the drain lock, from the drainer's ticks and, in the
background, from each session start while it is unfinished, so it also completes where no
drainer is installed. Each run scrubs at most `SB_SCRUB_MIGRATE_MAX_FILES` (50) files and starts
no new scrub after `SB_SCRUB_MIGRATE_MAX_S` (20 s). The first run lists only the files the scrub
would actually change in `~/.second-brain/.archive-scrub-v1.todo` (`<path>` and a failed-attempt
count per line), so an archive that merely mentions an id like `task-…` is not held back. A file
whose scrub fails goes to the back of the line. When the list is empty `.archive-scrub-v1` is
written and it never runs again.

What pauses until the scrub reaches a file:

- Extraction of that archive.
- Episodic recall of that session. The index skips (and drops) archives on the list, because 0.55
  had already indexed their text. Once an archive is scrubbed its rows come back; rows whose text is
  unchanged reuse their stored vector, so no model call is needed.

`sb status` shows `archive scrub:` as `done`, `N to scrub (...)`, `no to-do list yet` or `unknown`.
The health snapshot says the same in other words. With no drainer installed
(`SB_DISABLE_AUTO_TIMER=1`), the scrub still finishes over your next few session starts.

A window that failed extraction `SB_DRAIN_MAX_FAILS` times is dead-lettered and counted wherever it
sits in its archive, even in the middle. The SessionStart banner, `sb status` (`; dead windows: W in
A archives, L lines`), the health snapshot and the reconcile row all show those totals.

Old done-set rows stay valid; the new fields are additive.

## New state files

- `transcripts/.<archive>.lock` and `transcripts/.cursor-<key>.txt.lock`: write locks (the archive,
  and a session's cursor). The Stop/PreCompact append and the scrub take them (5 s wait). A lock is
  stolen only from a dead holder after 60 s, or after 600 s whatever the holder. The drainer
  deletes leftovers older than a day.
- `transcripts/.<archive>.evicted`: a mark left when the size cap removes an archive, so a
  re-created archive of the same name does not inherit the old position. The drainer cleans them.
- `observations/<sid>.sent`: how many tool-ledger lines the extractor already received.
- `.archive-scrub-v1` and `.archive-scrub-v1.todo`: the scrub migration marker and to-do list.
- `.last-archived-line-<slug>--<session>`: the archive cursor (above).
- `observations/<sid>.capped.flag` and `observations/<sid>.append-failed.flag`: the tool ledger
  reports a full ledger or a failed append once per session (one error-log row), not on every
  tool call. The drainer's 7-day observations sweep removes them with the ledgers.
- `.subagent-capture-no-jq`: present while `jq` is missing; subagent results are not archived and
  one error-log row says so. Removed on the first subagent stop with `jq` back.

The ledger is also compacted every drainer tick: it keeps one row per archive cursor plus the
dead-letter and retry rows past it, and drops rows of archives that were evicted. Nothing the
drainer reads changes.

## In-session capture: what else changed

- PreCompact now behaves like Stop when the LLM extraction fails: it merges the deterministic
  `[auto-captured]` files-changed decision (it merged nothing before), and a failed merge leaves
  the extraction marker in place, so the next Stop or PreCompact retries the window.
- A transcript record cut mid-write no longer hides the rest of the window: the tool-use gate and
  the files-changed floor parse each line on its own (one bad line used to make a real window read
  as "no tool use", and its marker moved past it).
- If the transcript part of the extractor input cannot be rendered, the hook does not send it; it
  logs the failure and merges the files-changed floor. The archived window is mined later.
- The subagent archive skips all four plugin agents, `raw-drainer` included (its reports were
  archived and mined again).
- The raw-inbox banner no longer says the drainer timer drains raw items: nothing does except
  `/second-brain:maintain`.

## Episodic index

The first index build after the upgrade converts old float rows to `e8`/`es` in place. Search never
rewrites the index. If you rebuild the index, a changed archive is re-parsed and a row whose text is
unchanged keeps its vector (no model call); only changed rows re-embed.

## If an older Claude Code session is still running

Close sessions that started before the upgrade once the upgrade is done. A running 0.55 MCP server
reads the old float format and errors on `episodic_search` once the index holds `e8` rows, until the
session is restarted. An old session's Stop hook also still archives the old way: it appends without the archive lock
and without scrubbing. The drainer scrubs any archive holding a credential before extracting it,
and the scrub re-checks the file size before it renames, so a lost append is unlikely, but it is
possible. Restart open sessions.

The size cap evicts differently now too: a `sub-*` subagent archive that is still waiting for
extraction is evicted only past three times the subagent cap, and the log names it.

## PreToolUse guard: Reads and out-of-scope calls are decided before the timeout

A Read, and a Write/Edit/MultiEdit that no locked rule matched, used to be decided only after
persona-tool-guard loaded lib.sh and jq: 1-4 s on a loaded Windows box, past the 5 s hook timeout
often enough that Claude Code cancelled the guard and ran the call. They are decided on the fast
path now. What you will see:

- A Read of a credential store asks (`credential-read`): `~/.ssh`, `~/.gnupg`, `~/.aws`,
  `~/.config/claude`, `~/.config/gh`, `~/.config/gcloud`, `~/.azure`, `~/.password-store`,
  `~/.netrc`, `~/.claude/.credentials.json`, `~/.git-credentials`, `~/.npmrc`,
  `~/.docker/config.json`, `~/.kube/config`, `~/.pypirc`, `~/_netrc`, `~/.config/git/credentials`,
  `~/.pgpass`, `~/.vault-token`, `~/.cargo/credentials` and `credentials.toml`,
  `~/.terraform.d/credentials.tfrc.json` and `~/.gem/credentials` (under your Windows profile too
  when `HOME` points elsewhere), plus `%APPDATA%\GitHub CLI\hosts.yml` and `%APPDATA%\gcloud` on
  Windows: the list symlink-guard guards writes into. It asks even inside the resource scope and
  with `SB_RESOURCE_SCOPE=off`. A rule of yours that denies such a Read still denies it.
- symlink-guard guards writes into those stores in two tiers. A write into `~/.ssh`, `~/.gnupg`,
  `~/.aws`, `~/.config/claude`, `~/.config/gh`, `~/.password-store`, `~/.netrc`,
  `~/.claude/.credentials.json` or `/etc` is denied, as before. A write into one of the stores new in
  this release (`~/.npmrc`, `~/.kube/config`, `~/.docker/config.json`, `~/.azure`, …, and the two
  `%APPDATA%` ones) asks you instead, so editing your `~/.npmrc` is one approval away. A path that
  looks like the second kind but leads into the first through a link is denied.
- On Windows a Read whose spelling cannot be compared with those stores asks as well: a UNC or
  `\\?\` device path (`windows-alias:unc`), NTFS stream syntax such as `.netrc::$DATA`
  (`windows-alias:stream`), and an 8.3 short name such as `SSH~1` that names no existing file
  (`windows-alias:8.3`; one that does is resolved and asks only if it is a store).
- The resource scope has a new root, `$PROJECT`: the directory the session was started in
  (`CLAUDE_PROJECT_DIR`). The call's `cwd` follows the session's shell `cd`, so after a `cd` into
  one of the project's worktrees the other worktrees were out of scope and every Read of them asked.
  A user `persona-rules.json` that declares its own `resource_scope.allowlist` replaces the default
  list as before; add `"$PROJECT"` to it to get the new root.
- A guard that cannot read a call or its rules because `jq` failed (it ran and exited non-zero, or
  its output stopped short) asks you to confirm the call; `error-log.jsonl` names the failure. With
  `jq` missing from `PATH` the call passes as before, one `error-log.jsonl` row says so, and the
  SessionStart banner reports the missing `jq` — except that persona-tool-guard still asks about a
  Read of a credential store and about a target longer than 4096 characters, which need no rule.
  When it cannot read the call at all without `jq` (bash older than 4.3, as macOS's `/bin/bash`, reads
  no field itself), it asks about a Read whose payload names a credential store's path anywhere.
  flow-guard then checks the call with `grep`, as it did before 0.56.0.

## Consolidation, delivery and guard changes in the same release

Nothing to do. These change what you see:

- **Safe-mode dream accept no longer stalls.** A page created in the live wiki after the dream's
  snapshot is kept, not counted as a deletion. When the apply cannot delete anything (no `rsync`,
  or no usable `created_at`), the no-delete check is skipped and an audit row
  (`gate=no-delete-check`) says why. A re-accept after a failed archive stamp only finishes the
  accept; it no longer re-applies forgotten pages or re-appends graph edges. The unattended lane
  logs why it is blocked (`gate=lane-defer`) instead of exiting silently.
- **Quarantine wording.** Only a CLI-version quarantine clears itself. Any other cause stays until
  you fix it and delete `~/.second-brain/.llm-maintain-quarantine` and `.llm-maintain-fails`; the
  banner names both.
- **The background dream-runner is confined.** Its Write/Edit/MultiEdit outside its own dream
  directory are denied, and its Bash grants are narrowed to the commands its steps run (`mv` and
  `rm` remain, unconfined). The inline `/second-brain:dream` is not confined. Any subagent
  Write/Edit that carries an agent id but no agent type is asked about when it targets a path
  outside every dream directory.
- **SessionStart memory is framed and folded.** Wiki descriptions, session-digest rows and
  persona signals sit inside the untrusted-reference frame, with brackets, look-alike brackets,
  control and invisible characters folded so stored text cannot close the frame. The enrichment
  query now uses the project's most frequent words, not the alphabetically first ones.
- **Local docs are offered as `Read <path>` lines,** only when the path is absolute and inside the
  active project root; others are dropped with a `gate=local-doc-drop` audit row.
- **`episodic_search` says when vector search is unavailable** instead of "No matching
  conversations found".
- **`discover-installed.sh` prints nothing at SessionStart.** The catalog is still written to
  `~/.second-brain/.installed-catalog.json`; it was never injected.
